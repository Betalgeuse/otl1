# v0.0.26 관리자 권한 보호

2026-09-11. 관리자 권한은 Slack 서명 검증을 통과한 요청의 워크스페이스·사용자 ID·관리 채널 ID로 판단한다. 표시 이름, ‘나는 관리자’라는 자연어, LLM 판단, 버튼의 ownerId만으로 권한을 부여하지 않는다.

## 사용 방법

관리자 본인이 비공개 `admin-dev`에 아래 문장을 남긴다.

| 입력 | 결과 |
| --- | --- |
| 회원 현황 | daily-scrum의 당일 원씽·완료·후기·휴식을 admin-dev에 표시 |
| 업데이트 관리 | 버전 선택과 게시 미리보기. 게시 버튼은 관리자만 실행 |
| 피드백 보기 | townhall에 저장된 버전별 의견을 admin-dev에서 조회 |
| 공통 안내 설정 | 현재 관리 채널의 공통 안내 설정·QA. 별도 ‘원씽 채널에 10시·18시 적용’ 버튼은 실제 daily-scrum 전환 |

공개 채널에서는 관리자 본인도 관리 기능을 사용할 수 없다. 일반 회원은 자기 기록·개인 알림·샤라웃을 사용한다. QA 버튼은 관리자 전용 관리 채널에서만 표시한다.

## 구현 경계

- `src/community-permissions.ts`: 단일 관리자 검사와 명시적 허용 동작 목록. 관리자 설정 누락, 관리 채널과 공개/게시 채널 중복은 거부.
- `community-admin.ts`, `community-releases.ts`, `community-cutover.ts`, `community-controls.ts`: 실제 조회·설정·게시 함수에서도 공통 권한 검사. 흩어진 ID 검사 통합.
- `community-interactions.ts`: 저장소 생성 전에 권한·요청 종류·모달 작성자 검사. 알 수 없는 동작은 거부. 기존에 열린 작성자 정보 없는 모달은 다시 열어야 한다.
- `community-events.ts`: 거절 사유를 안내하며 관리자 데이터를 반환하지 않는다.

이는 봇 내부 기능의 권한이다. Slack 자체 워크스페이스 관리 권한이나 Cloudflare·Neon 계정 접근 권한을 변경한 것은 아니다. 비공개 여부는 지정한 채널을 운영자가 유지해야 한다. 현재 admin-dev는 실제 화면에서 private, 회원 1명으로 확인했다.

## 검증

`qa/community-admin-access.mjs`: 비관리자·다른 팀·공개 채널의 관리자 명령/버튼/함수 거절, 외부 효과 없음, 관리자 설정 누락, 모달 소유자 불일치, QA 버튼 노출 제한.

`qa/community-townhall.mjs`: 기존 게시 미리보기·중복 게시 방지·피드백 조회 회귀 통과. lint·타입 검사·빌드 및 기존 언어·리액션·예약 계산 검사 통과.

`qa/community-admin-live.mjs`: 배포 HTTP에 서명된 합성 요청 16건을 보내 관리자/일반 회원의 공개 채널 관리 동작 거절 확인. 다른 회원의 실제 계정으로 로그인한 테스트는 아니다.

실제 관리자 프로필로 admin-dev에서 공통 안내 요청 → 버튼 → 모달 → 기존 비활성 설정 저장을 수행했다. 저장 응답: https://onething1line.slack.com/archives/C0C0AMK8068/p1789060987399869 . 공개 게시 버튼은 실행하지 않았다.

최종 배포 ID·파일 해시·HTTP 근거: `.omx/qa/admin-access/release.json`, `live-http.json`. 버전 계획의 구 v0.0.26~54는 신 v0.0.27~55로 이동했다.
