# v0.0.45~49 환영·첫 기록 축하·안내글

## v0.0.45 환영에 전체 알림

새 회원의 townhall 환영 글에서 ‘다들 환영 이모지 하나씩 부탁해요!!!’ 뒤에 Slack의 전체 채널 멘션 `<!channel>`을 붙인다. Slack의 표준 전체 알림은 @channel이며 @all이라는 사용자 그룹을 새로 만들지 않는다. 중복 입장 이벤트로 같은 회원 환영을 다시 발송하지 않는다. 과거 글 수정으로 모든 기기의 푸시 수신을 보장하지는 않는다.

## v0.0.46 첫 등록·완료·후기 봇 축하

첫 목표 등록, 첫 목표 완료, 첫 후기는 각기 다른 이정표다. 기존 최초 완료를 의미하던 firstGoal과 별도로 firstRegistration을 DB에서 원자적으로 기록한다. 기존 기록과 변경 이력에 등록이 있었던 회원은 출시 시 첫 등록 이력을 보존하므로 다음 수정 때 가짜 첫 등록 축하가 생기지 않는다.

공개 ONE THING 채널의 첫 기록은 봇이 townhall의 **새 최상위 메시지**로 직접 게시한다. 해당 스레드에 동료 샤라웃 버튼을 붙이는 방식이 아니다. 회원이 직접 보내는 샤라웃 기능은 별개로 유지한다. 최초 후기의 인정은 기존 정책대로 원문이 저장된 경우이며 목표가 부분 진행/미완료여도 후기 참여는 축하할 수 있다.

회원·목적 채널·종류별 발송 claim으로 중복을 막고 결과 메시지의 목적 채널을 저장한다. 원래 변경을 되돌리면 townhall 축하도 정정한다. 첫 축하를 되돌렸다고 새 첫 축하 권한을 무한히 재발급하지 않는다. 개인 QA는 admin 채널에만 게시해 실제 townhall에 시험 내용을 섞지 않는다.

## v0.0.47 안내글 발행본 보존

관리자가 작성한 지정 원본 안내글을 읽는다. 원본 본문·작성자·원본 메시지 및 편집 시각·본문 SHA256을 guide_versions에 보존한다. 관리자가 Slack 원본을 편집하면 이후 신규 회원에게 바뀐 본문을 전달하고, 과거 전달 당시 버전은 보존한다. 별도 편집/발행 모달까지 구현한 것은 아니다. 현재 원본 편집은 즉시 다음 전달에 적용되는 운영 방식이다.

본문의 서비스명 표기만 ONE THING으로 맞추며 초대 인원 등 운영 정책을 임의로 바꾸지 않는다. 복사된 안내글의 기존 전체 멘션 토큰은 일반 텍스트로 바꿔 신규 입장마다 가이드에 포함된 전체 알림을 재발송하지 않는다.

## v0.0.48 신규 회원 멘션·안내글 전문 게시

welcome-start-here 입장 이벤트에 따라 해당 회원을 멘션하고 최신 안내글 **전문을 새로운 채널 메시지**로 올린다. townhall 환영과 독립적인 경로라 두 채널 입장 순서에 상관없이 실행된다. 일반 메시지와 입장 전용 이벤트가 함께 와도 회원·채널별 guide_deliveries 기본키로 한 번만 게시한다. 봇·삭제 계정은 제외한다.

관리자 원본을 확인하지 못하면 임의 내용을 생성하지 않는다. 실패 또는 전송 결과가 불확실한 건은 실패 상태로 남겨 운영자가 실제 채널과 대조한다. 무조건 자동 재발송해 중복 게시하지 않는다. 출처 삭제·영구 API 오류를 자동 치유하는 것은 아니다.

## v0.0.49 ONE THING 표기

봇 안내·축하·상태 제목은 서식이 가능한 곳에서 **ONE THING**으로 표시한다. Slack 버튼·모달 레이블·이미지 대체 텍스트처럼 plain_text만 가능한 곳은 ONE THING으로 표시한다. 사용자 목표·후기 원문을 저장할 때 브랜드 치환하지 않는다. 입력의 ‘원씽’ 표현은 계속 인식한다.

## 검증

- SQL009: guide FK·버전 불변·회원당1전달·실패/중복 상태. SQL010: 최초 등록1회·중복·내용 수정 제외·첫 완료/첫 후기 별도.
- community-guide: 다른 채널/봇/비관리자 원본 차단, 중복·동시 전달 claim, 원본 수정과 새 회원 버전, 전송 실패 보류.
- townhall-milestones: 새 최상위 메시지, 동료 샤라웃 버튼 없음, 중복 제거, undo 목적 채널, private QA 격리.
- brand-copy: 서비스 제목의 bold, plain 레이블, 사용자 목표·후기 원문 보존.
- 실제 확인: 오늘 신규 회원의 welcome 안내 전문1건과 기존 환영글 전체 멘션을 수정했고, 기존 스레드에 잘못 올라간 첫 후기 축하1건을 townhall로 옮겼다. admin에서는 첫 등록·첫 후기 테스트 메시지가2개만 생성되고 재실행으로 늘지 않음을 확인했다. 모든 일반적인 실패나 기기푸시를 보장한다는 의미는 아니다.

개인 원문·채널 식별자·실제 메시지 영수증은 `.omx/qa/social-onboarding/`에 보관하며 공개 저장소에는 포함하지 않는다.

첫 기록 축하 전송은 잔디 렌더링·추가 AI 응원보다 먼저 실행해, 부가 처리의 실패로 축하가 누락되는 결합을 끊었다. 사용자 목표·후기의 이모지도 무작위 치환하지 않고 봇이 쓴 앞뒤 문구에만 커스텀 이모지를 적용한다. 발송 실패/응답 불확실은 로그·dispatch 기록을 대조해 복구해야 하며 분산 트랜잭션 또는 무조건 재시도를 구현한 것은 아니다.
