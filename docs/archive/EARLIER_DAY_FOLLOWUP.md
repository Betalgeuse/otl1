# v0.0.31 이전 날짜 원씽 후속 안내

잔디 조회·새 기록 저장 결과 카드에서 미정리된 이전 날짜를 안내한다. 별도의 예약 멘션을 추가하거나 새 목표 등록을 막지 않는다. 최근3일의 미정리 날짜를 보여주고 나머지는 개수로 표시한다. 여기서3일은 연속 달력 날짜가 아닌 미정리 기록3건이다.

| 상태 | 처리 |
| --- | --- |
| 목표 있음·완료 여부 미확인·후기 없음 | 완료 여부와 후기 요청 |
| 목표 있음·후기 있음·완료 여부 미확인 | 완료 여부만 요청 |
| 완료/부분 진행/미수행·후기 없음 | 후기만 요청 |
| 완료/부분 진행/미수행·후기 있음 | 안내 제외 |
| 휴식 | 안내 제외 |
| 목표 없음·오늘·미래 | 이전 날짜 안내에서 제외 |

답변하지 않았다는 이유로 미완료 처리하지 않는다. 이미 쓴 후기를 재작성하도록 요구하지 않는다. 과거 수입 기록에 원문 링크가 있으면 해당 글 링크를 표시하고, 그 외에는 날짜와 해당 날짜 글의 스레드에 답변하라는 안내를 표시한다. 과거 메시지의 삭제 여부까지 자동 확인하지 않는다.

날짜 연결 순서: 서버에 저장된 prompt의 대상일 → 본인이 작성한 원본 incoming의 대상일 → Slack 루트 메시지 시각의 한국 날짜. 답글을 오늘 작성했다는 이유로 오늘 날짜에 저장하지 않는다. 과거 변경은 기존 확인 과정을 유지하고 대상 날짜를 명시한다. 버튼도 ‘오늘 쉬어요’ 대신 ‘이날 쉬었어요’라고 표시한다. 다른 회원의 소유자·채널 검사와 expectedRevision을 유지하며 LLM은 저장 날짜를 결정하지 않는다.

같은 날 후기가 추가되거나 휴식 처리되면 다음 상태 조회에서 제외된다. 기존에 게시한 카드의 안내 문구가 실시간 수정되는 것은 아니다. 이전 안내를 따라 답글을 달더라도 저장 전 최신 상태·revision을 다시 확인한다.

검증: `qa/community-followup.mjs`의 상태 조합·원본 날짜 우선순위, 기존 권한·townhall·환영·리액션 회귀, lint/typecheck/build. admin-dev에서 9/10 테스트 목표를 마련하고 실제 사용자 프로필로 부분 진행 후기를 제출 → 대상 날짜 확인 → 일부 진행 버튼 →9/10 후기 저장을 확인했다.9/11 레코드는 전후 완전히 동일했고, 처리된9/10이 안내에서 빠지는 것을 검증했다. 운영 회원에게 시험 안내를 발송하지 않았다. QA 원문·검증 자료는 추적에서 제외된 `.omx/qa/earlier-day/`에 있다.
