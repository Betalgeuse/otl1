# 초대 기반 참여 · 구현 중

현재 초대 발급·수락과 비회원 차단 코드는 로컬에서 구현·검증했다. 공개 잔디 배포에는 코드가 포함되지만 `INVITATIONS_ENABLED=false`로 꺼져 있다. 아래 migration은 운영 Neon에 적용하지 않았다. 팀 구성 방식과 최초 운영자 지정은 별도 확정이 필요하다.

## 무료 Slack에서 지켜야 할 경계

봇은 원씽 참여 자격과 초대권을 관리한다. 무료 Slack의 워크스페이스 가입은 관리자 승인 절차를 함께 적용해야 한다.

1. Slack Admin → Workspace settings → Permissions → Invitations에서 Require admin approval을 켠다.
2. 기존 공용 초대 링크를 비활성화하고, 초대 없이 가입할 수 있는 설정이 있으면 해제한다.
3. 운영자는 봇에 유효한 초대가 있는 이메일의 Slack 가입 요청만 승인한다.

[Slack 공식 안내](https://slack.com/help/articles/115004854783-Require-admin-approval-for-invitations-to-Slack)는 관리자 초대 승인이 모든 요금제에서 가능하며, 초대 요청 관리 API는 Enterprise 조직용이라고 명시한다. 봇 코드만으로 Slack 관리자 자신의 승인·초대 동작까지 강제할 수 있다고 주장하지 않는다. 현재 워크스페이스의 위 설정을 변경하거나 검증하지 않았다.

## 초대 규칙

- 한국 시간 기준 달력 월마다 참여자당 초대권 1장. 이월하지 않는다.
- 발급 시 사용하며 미수락·만료로 복구하지 않는다. 당월 만료 시 새 초대가 필요하다.
- 같은 달 같은 사람에게 재요청하면 기존 코드를 보여주며 추가 차감하지 않는다.
- 초대받은 이메일과 Slack 계정 이메일이 일치하는 활성 일반 사용자만 수락할 수 있다.
- 봇은 메일·DM을 발송하지 않는다. 초대자가 사람에게 직접 코드를 전달한다.
- 회원 가입과 초대 사용 기록을 하나의 트랜잭션에서 반영한다.
- 초대가 없으면 기존 기록의 조회·작성·완료·색상 변경과 설정창 접근을 차단한다. 기존 목표가 있다는 이유로 회원 자격을 자동 부여하지 않는다.

## 명령

- `/one 초대`: 이번 달 남은 초대권.
- `/one 초대 상대방이메일`: 대상자에게 묶인 초대 코드 발급 또는 기존 코드 조회.
- `/one 가입 초대코드`: Slack 가입 후 초대 수락.
- `/one 초대확인 이메일`: 최초 운영자가 Slack 가입 승인 전에 유효한 초대를 확인.

초대 정보는 개인 응답으로만 전달한다. 공개 채널 공유 명령은 새 버전에서 중단한다. 팀 조회는 팀 범위가 결정된 뒤 연결한다.

## 설치 조건

- `INVITE_SIGNING_SECRET`: 초대 코드와 이메일 해시 생성에 쓰는 별도 무작위 비밀키. 값은 기록하거나 공개하지 않는다.
- `COMMUNITY_OWNER_ID`: 최초 운영자의 Slack 멤버 ID. 등록 시 실제 활성 워크스페이스 관리자임을 확인한다.
- Slack 권한: commands, users:read, users:read.email. 권한 추가 후 앱 재설치가 필요하다.
- 후보 migration: 002_invitation_tables.sql → 003_invitation_functions.sql → 004_membership_guard.sql.
- 운영자 등록: 위 migration과 운영자 확인이 끝난 뒤 `node scripts/bootstrap-owner.mjs`. 처음 요청한 사용자를 자동 운영자로 등록하지 않는다.

DB에는 원문 이메일이나 원문 초대 코드를 저장하지 않고 HMAC 이메일 해시와 코드 해시를 저장한다. 초대 비밀키를 바꾸면 기존 이메일 바인딩과 미사용 코드에 영향이 있으므로 키 교체는 별도 이관이 필요하다.

## 검증

격리한 PostgreSQL에서 12개 동시 발급 요청 중 한 개만 발급되고, 12개 경쟁 수락 요청 중 한 회원만 생성되는 것을 확인했다. 만료·재시도·이메일 바인딩·기존 기록 보존·비회원 5개 기록 동작 거부도 통과했다.

실제 로컬 HTTP → Neon 프로토콜 대역 → 실제 PostgreSQL 흐름에서 초대·재조회·잘못된 수신자 거부·수락·가입 후 원씽 작성·비회원 설정창 거부를 검증했다. Slack 사용자 조회와 메시지 전송은 대역으로 확인했으며 실제 메시지는 보내지 않았다.

## 남은 결정

- A가 B를, B가 C를 초대할 때 A·B·C가 같은 팀인지, A·B와 B·C가 별도 팀인지.
- 최초 운영자 Slack ID.

둘이 결정되기 전에는 팀 배정 완료나 전체 초대제 운영 완료로 보고하지 않는다.
