## 2026-09-18 v0.0.55 welcome 발행본 구현

welcome 안내를 변경 가능한 Slack 원문에서 신규 회원 입장 때마다 복사하던 구조를 폐기했습니다. 관리자가 `v0.0.55`와 원본·편집 시각, OT1L 로고·daily scrum 이미지 순서, 예상 canonical hash를 명시적으로 발행하면 migration 026이 정제 본문과 원본 metadata를 하나의 최신 발행본으로 고정합니다. Slack 원문 편집만으로는 전달본이 바뀌지 않습니다. migration 028은 Worker의 최신 발행본 조회·가입 전달과 관리자의 발행·대상 복구를 서로 다른 DB 역할과 자격증명으로 분리하고 `PUBLIC` 함수 실행 권한을 회수합니다. 신규 회원 자동 안내는 DB 최신 발행본만 읽고, 전체 채널 알림은 일반 텍스트로 바꿉니다. 전달 식별자에 불변 content hash를 포함해 같은 회원·같은 hash는 멱등 처리하고 새 hash의 수정본은 한 번 더 전달할 수 있습니다. 가입 안내와 특정 회원 수정본은 OT1L 봇 토큰으로만 게시하고 Slack 응답의 봇 작성자와 message timestamp를 확인·저장합니다. 운영 발행과 지정 회원 수정본은 Slack Web에서 봇 작성자·본문·이미지 순서를 확인했습니다. 배포 뒤 실제 신규 회원의 자연스러운 입장 이벤트부터 최종 게시까지는 아직 관찰하지 않았습니다.

## 2026-09-18 회원 기준 일괄 수집 운영 안정화

daily-scrum의 완전한 Slack 회원 목록을 실행 시점마다 확인하고, 이탈·삭제·봇 계정을 제외한 목표·후기 대상자를 공개 채널의 일괄 메시지로 묶습니다. migration 027은 오래된 스냅샷을 무시하고 재입장에도 기존 기록·시각·opt-out을 보존하며, 공통 글과 개인 due 일괄 글을 독립된 lease·최대 세 번 재시도·정확한 history 대조로 관리합니다. 대상자가 많으면 100명과 Slack 본문 한도 안에서 결정적으로 나눕니다. 10시·18시는 공통 현재 회원 수집이고, 11시·20시는 개인 기본값일 뿐 저장된 시각과 opt-out이 우선합니다. 토요일은 10시 선택 참여 글 한 번만 멘션 없이 보내고 일요일은 보내지 않습니다. 비공개 관리 채널의 수집 테스트와 현재 회원 일괄 게시를 Slack Web에서 확인했지만, 2026-09-19 주말 자연 실행과 2026-09-21 월요일 자연 실행은 아직 관찰 전입니다.

## 2026-09-18 후기 우선 저장과 선택적 결과 확인

완료 상태가 없는 유효한 후기는 버튼 응답을 기다리지 않고 먼저 저장하고 잔디와 반응을 갱신하도록 변경했습니다. 완료·부분 완료·미완료·휴식은 같은 공개 스레드에서 버튼 또는 짧은 자연어로 선택할 수 있습니다. 질문 전송 실패는 durable delivery로 재시도하며 후기 저장을 되돌리지 않습니다. 중복 이벤트, 오래된 버튼, 다른 사용자 선택은 기록을 다시 쓰지 않습니다. 이 항목은 코드와 합성 QA까지만 완료했으며 운영 배포와 실제 Slack Web QA 전입니다.

### 2026-09-18 브라우저 QA 후속 보정

`후기:`·`회고:` 머리말은 저장 본문에서 제거하고, 본문의 숫자·시간·버전·`어제보다` 표현을 날짜 지시로 오인하지 않도록 선두 날짜 문법만 사용합니다. 이미 같은 결과가 적용된 `부분완료` 등의 재입력은 pending 확인만 닫고 이벤트·반응·잔디 카드를 추가로 만들지 않습니다. 합성된 서명 Slack 이벤트와 전체 검사로 고정했으며 운영 배포 전입니다.
