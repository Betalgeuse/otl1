# OT1L 업데이트 목록과 운영 단계

갱신: 2026-09-10. 상태: 우선순위 인터뷰 중, 문서에서만 관리. [버전별 업데이트 목록·변경 이력](UPDATE_HISTORY.md).

우선순위를 판단하고 새 요구를 배치하는 기준은 [제품 우선순위와 운영 원칙](PRODUCT_PRINCIPLES.md)을 따른다. 이 문서는 세부 운영 정책과 미해결 질문을 관리한다.

## 확정 방향

- 당장은 무료 운영한다. 이후 운영자에게 실제 이익이 남는 사업 구조로 발전시킨다. 매출 발생과 이익 발생을 구분한다.
- 지인의 실제 성취가 초대자의 좋은 결과로 이어져야 한다. 구체적인 경제 보상과 지급률은 미정이다.
- 무료 운영 인원과 다음 단계 전환 기준을 정하고 문서에서 버전별 업데이트 목록을 관리한다. townhall 발송은 현재 요청 범위가 아니며 별도 게시 요청 전에는 보내지 않는다.
- 참여하지 않는 회원의 자동 퇴장 흐름을 계획한다. 누구를 언제 어디에서 제외할지 아직 정하지 않았고 자동 퇴장은 시행하지 않는다.
- 초대장은 별도 홈페이지에서 관리하고 카카오톡 또는 LinkedIn 정보를 연결한다. 입력할 정보의 형태와 확인 방법은 미정이다.
- ‘오늘 쉬기’는 사유 없이 당일 참여를 마무리한다. 휴식, 미완료, 후기 미제출, 장기 미참여를 같은 상태로 취급하지 않는다.
- 카카오 알림은 후기뿐 아니라 원씽 등록 등 사용자가 해야 하지만 아직 하지 않은 행동을 안내한다. 무엇이 의무인지는 운영 규칙으로 정하며 LLM이 임의로 의무를 만들지 않는다.

## 인원과 단계: 논의를 시작하기 위한 제안

인원수는 수요·운영시간 실측으로 검증한 최적값이 아니다. 확정 정원이나 유료화 약속으로 공지하지 않는다. 유료 전환 시 기존 회원 적용 여부도 별도 결정한다.

| 단계 | 인원 제안 | 먼저 확보할 것 | 다음 단계 검토 조건 |
| --- | --- | --- | --- |
| 1. 무료 소규모 운영 | 활성 회원 최대 30명 후보 | 본인 목표·후기·휴식 상태의 정확한 저장, 운영자 확인, 초대 관계 매핑 | 상태 변경 오작동과 오알림 해결, 주간 운영시간 측정 |
| 2. 무료 운영 확장 | 최대 50명 후보 | 초대 홈페이지, 회원 상태·휴식·복귀 관리, 최신 가이드와 온보딩 | 4주 운영을 관찰하고 사람당 지원 비용·지속 참여·운영 부담 확인 |
| 3. 유료 상품 검증 | 50명에 도달했다고 자동 과금하지 않음 | 누가 무엇에 지불하는지, 제공 원가, 보상 재원, 기존 회원 조건 | 실제 지불 의사와 제공 가능한 가치, 보상 후 기여이익을 확인한 뒤 시행 결정 |

활성 회원은 집계일 기준 현재 참여 자격이 있는 사람으로 정의하는 안이다. 휴식·유예 회원을 정원에 포함할지, 대기 명단을 둘지 미정이다. 누적 가입자 수와 실제 관리 인원을 분리한다. 인원만 늘었다고 운영 준비가 끝났다고 보지 않는다.

## 버전별 업데이트

작업 식별자는 제품 버전으로 통일한다. [버전별 목록](UPDATE_HISTORY.md)에 변경 하나당 버전 하나로 매핑하고 완료·선행 조건·상태를 기록한다. 이 문서는 운영 정책 배경과 미해결 질문을 관리하며 백로그를 중복 유지하지 않는다.

현재 v0.0.1~v0.0.19는 실제 저장·확인·되돌리기·반응·지원 기능을 포함하며 admin-dev 사용자 QA를 마쳤다. [릴리스 결과](RELEASE_V001_V019.md). 이전 파일럿과 구분한다. v0.0.1·v0.0.5 자연어 등록·완료 반영을 직접 검증했다. 명확한 입력은 처리 결과와 되돌리기를 제공하고 애매한 입력만 확인하는 방향이다. [현재 LLM 검증 범위](LLM_PILOT_RESULTS.md)

## 풍부한 반응과 선제적 원씽 대화

원씽을 남기면 저장 확인에 더해 풍부한 이모지와 응원으로 환영한다. v0.0.2는 등록 이모지, v0.0.4은 등록 응원 댓글, v0.0.6는 완료 축하 이모지, v0.0.8은 후기 공감 댓글이다. 각각 실제 기록 상태에 맞춰 원문이나 스레드에 반응하고 같은 사건을 반복 처리하지 않는다. 저장 실패를 성공 이모지로 덮지 않는다.

여러 이모지를 쓰는 방향은 사용자 요구다. 어떤 이모지를 몇 개 달지, 모든 등록에 댓글을 달지, 댓글·DM·카카오를 얼마나 자주 보낼지는 아직 미정이다. 운영자 설정과 회원별 선호를 통해 빈도와 균형을 맞추는 안이다. 특정 회원만 반응을 독점하지 않도록 신규·조용한 회원의 기록도 챙긴다. 사람의 실제 응원과 봇 반응은 구분한다.

v0.0.40는 의무 누락 안내와 별개로, 습관이 끊기기 전에 원씽 대화를 먼저 시작한다. 예: ‘오늘 가장 중요한 한 가지는 무엇인가요?’, ‘어디까지 해보셨나요?’, ‘오늘 다시 시작할 작은 한 가지를 정해볼까요?’ 같은 대화다. 기존 등록·후기 안내와 접촉 한도를 공유하고 답변·휴식·중지 후에는 중복 접근하지 않는다. 초기 문구는 고정 템플릿으로도 만들 수 있으며 모든 반응에 LLM을 호출할 필요는 없다.

## 서로 샤라웃하는 흐름

- v0.0.10: 회원이 동료에게 샤라웃을 보낸다. 누구에게 어떤 실천·도움에 대해 보내는지 원문과 함께 연결한다. 상대를 잘 모르는 회원도 구체적인 원씽을 보고 응원할 수 있게 한다.
- v0.0.11: 봇이 먼저 샤라웃을 제안한다. 예: ‘오늘 첫 원씽을 해낸 동료가 있어요. 함께 축하 한마디 남겨볼까요?’ 작성자가 보낼 내용을 선택·확정하며 제안을 무시해도 불이익을 주지 않는 안이다.
- v0.0.12: 첫 원씽 완료가 저장되면 봇이 첫 달성을 샤라웃하고 동료의 축하로 연결한다. 첫 목표 등록과 첫 목표 완료를 구분한다.
- v0.0.13: 첫 인정 후기가 저장되면 봇이 첫 후기를 샤라웃하고 동료의 응원으로 연결한다. 미완료 사유를 담은 첫 후기도 후기 기준을 충족하면 축하 대상이다.

첫 달성은 회원·이정표별로 한 번만 처리한다. 기존 기록이 있는 회원을 기능 출시 후 처음 본다는 이유로 첫 달성자로 부르지 않는다. 과거 이력이 불명확하면 첫 여부를 확인할 때까지 일반 축하로 처리하는 안이다. 완료 취소·후기 삭제 후의 재입력으로 첫 샤라웃을 반복 발급하지 않고 잘못 게시된 축하는 정정한다.

첫 완료와 첫 후기가 같은 글에서 동시에 발생하면 두 이정표를 각각 기록하되 공개 축하는 한 메시지에 묶을 수 있다. 기존 일반 축하·후기 댓글과도 중복 조정해 반응은 풍부하게, 알림은 균형 있게 유지한다. 제안 대상은 특정 회원이나 초대자에게만 고정하지 않으며 반응이 적은 기록도 챙기는 안이다.

게시 위치는 원문 스레드·원씽 채널·별도 축하 공간 중 미정이다. townhall 업데이트 공지와 자동으로 같은 채널에 게시하지 않는다. 제안 빈도, 회원별 선호, 공개 범위, 첫 기록 기준·정정 방식은 인터뷰에서 정한다. 샤라웃을 경제 보상이나 신뢰 점수로 바로 환산하는 규칙은 아직 없다.

## 필수 행동 누락 안내

알림은 ‘행동의 의무 여부’와 ‘수행 상태’를 기준으로 만들고, Slack·카카오는 전달 채널로 구분한다. 카카오를 후기만 보내는 기능으로 제한하지 않는다.

| 행동 | 안내 대상 | 안내 종료 조건 | 버전·결정 상태 |
| --- | --- | --- | --- |
| 오늘 원씽 등록 | 해당일 참여 대상이고 원씽이 아직 없는 회원 | 등록 완료, 오늘 휴식, 참여 대상 제외, 알림 중지·철회 | v0.0.19·v0.0.47, 시각·횟수 미정 |
| 오늘 후기 제출 | 해당일 후기 대상이고 후기가 아직 없는 회원 | 후기 제출, 오늘 휴식, 참여 대상 제외, 알림 중지·철회 | v0.0.17·v0.0.46, 시각·횟수 미정 |
| 수행 상태 확인 | 본인 확인이 필요한 상태 | 본인의 상태 확인 또는 요청 취소 | 필수 여부·알림 필요성 미정, 버전 미배정 |
| 가입 절차·가이드 확인 | 운영상 반드시 필요한 절차를 끝내지 않은 회원 | 해당 절차 완료 또는 참여 취소 | 어떤 절차가 의무인지 미정, 버전 미배정 |

각 안내에는 대상 행동, 대상일, 언제까지 해야 하는지, 바로 할 수 있는 입력 위치, 미루기·휴식·지원 중지 방법을 연결하는 안이다. 원씽 등록 안내는 등록 위치로, 후기 안내는 대상일 후기 위치로 연결한다. 마감이 미정이면 임의로 지각 판정을 하지 않는다.

여러 행동이 누락돼도 개인별 총 알림 한도를 공유한다. 원씽이 없는 사람에게 등록 안내와 후기 안내가 동시에 쌓이지 않도록 선행 행동과 안내 우선순위를 정한다. 구체적인 시간·횟수는 아직 정하지 않았다. 발송 직전 저장 상태와 동의를 다시 확인하고, 수집 장애·애매한 LLM 해석은 미수행 증거로 쓰지 않는다.

휴식은 당일 원씽·후기 안내를 종료한다. 연락처 확인 같은 별도 가입 절차까지 자동 완료시키지는 않는다. 안내 대상 선정과 자동 퇴장 판정도 별개이며, 안내를 받았다는 이유로 퇴장 조건을 충족했다고 보지 않는다.

## 자동 퇴장 설계에서 먼저 결정할 것

사용자가 원하는 자동 퇴장 방향을 반영하되, BM을 먼저 정했다고 곧바로 시행 가능한 것은 아니다. 현재 무료 단계에도 참여 정책은 필요하고 유료 단계에서는 결제·환불·접근 종료 정책이 추가로 필요하다.

검토 흐름: 참여 대상일 확인 → 미참여 후보 판정 → 본인 안내 → 휴식·정정·복귀 기회 → 유예 종료 확인 → 합의한 범위에서 제외. 첫 운영은 자동 제외 대신 운영자에게 후보를 보여주는 방식으로 판정 정확도를 확인하는 안이다.

미정 사항:

- 원씽 ‘미완료’인가, 목표·후기·휴식 의사 없이 ‘미응답’한 것인가?
- 연속 몇 번 또는 일정 기간 중 몇 번인가? 주말·휴무·첫 가입일은 어떻게 다루는가?
- 휴식 선택을 반복할 때 장기 휴식으로 전환할 것인가? 휴식의 무기한 사용을 현재 허용하거나 금지한 것으로 간주하지 않는다.
- 제외 대상은 실천 프로그램 좌석, Silo/채널, 커뮤니티 참여 자격, Slack 워크스페이스 계정 중 무엇인가?
- 본인에게 안내할 시점과 유예 기간, 초대자에게 공개할 정보, 재초대·복귀 조건은 무엇인가?

후기 수집 오류나 LLM의 분류만으로 퇴장하지 않는다. 본인 확인 상태와 미리 정한 운영 규칙을 사용한다. Slack에서 필요한 제외 기능의 플랜·권한·API 지원 여부는 범위가 정해진 뒤 확인한다. 현재 퇴장 기능이 있다고 안내하지 않는다.

## 초대 홈페이지의 첫 범위

제안 흐름: 초대자가 로그인 → 사용 가능한 초대권 확인 → 초대장 생성 → 지인에게 공유 → 지인이 초대자·커뮤니티 안내·공개 범위를 확인 → 초대 수락 → Slack 본인 계정 연결 → Silo 배정 확인.

- 초대 URL은 만료·취소·1회 수락을 지원하는 안이다. 다시 수락하거나 링크를 전달받았다고 다른 초대자 관계를 덮어쓰지 않는다.
- 카카오톡 정보는 개인 프로필 링크·오픈프로필·ID·로그인 연동 중 무엇인지 미정이다. LinkedIn도 프로필 URL 입력과 OAuth 연결은 별개의 선택이다.
- 입력한 링크만으로 지인 관계나 본인 여부가 검증됐다고 하지 않는다. 첫 버전에서는 초대자와 초대받은 사람의 상호 확인 및 Slack 계정 연결을 검토한다.
- 카카오 연락처를 등록하는 것과 서비스 알림 수신 동의는 별개다. 외부 연락처를 공개 townhall이나 순위판에 표시하지 않는다.
- 초대 정책은 이전 월 1장 요구와 welcome 가이드의 현재 2명 사이 적용 관계가 미정이다. 홈페이지에 새 발급량을 임의로 넣지 않는다.

- v0.0.54: 연결된 본인이 카카오에 쓴 명확한 원씽을 저장하고 Slack 지정 채널에 봇이 출처·작성자를 표시해 올린 뒤 카카오로 결과를 안내한다. 별도 슬래시 명령이나 Slack 재입력을 강제하지 않는다.
- 홈페이지에 카카오 프로필을 적는 것과 실제 메시지 수신 권한·본인 연결은 다르다. 카카오 수신 경로와 플랫폼 지원은 구현 전 확인할 외부 조건이다. 알림톡을 보내는 기능만으로 회신 수신이 가능하다고 가정하지 않는다.
- 연결 과정에서 어떤 내용이 어느 Slack 채널에 공개되는지 설명한다. 개인 대화 전체를 복사하지 않고 원씽 등록 의도가 분명한 문장만 처리한다. 애매한 내용은 카카오 안에서 확인한다.
- 목표 저장과 Slack 게시의 상태를 분리한다. 저장 후 게시가 실패하면 저장 성공을 유지하고 게시만 재시도하며, 메시지 재수신에도 목표를 중복 생성하지 않는다. 등록 실패는 실패로 안내한다.
- 첫 수신 범위는 목표 등록 하나다. 후기·완료·휴식의 카카오 입력 처리는 요청·정책이 정해지면 별도 버전으로 추가한다.

## townhall 업데이트와 피드백 기능

- v0.0.14: 운영자가 선택한 검증 완료 버전의 변경·사용법·제한을 townhall에 게시하고 게시물과 버전을 연결한다.
- v0.0.15: 해당 업데이트에 달린 피드백을 버전·원문·작성자에 연결해 운영자가 조회한다. 자동 우선순위 변경이나 회원 의견의 자동 채택은 하지 않는다.
- 게시 방식·피드백 수집 범위는 인터뷰에서 정한다. 기능을 계획에 추가한 것이 지금 Slack에 게시하라는 뜻은 아니다. 현재는 문서만 관리한다.
- 신규 버전은 우선순위와 선행 조건에 맞춰 삽입하고 미출시 번호·참조를 함께 갱신한다. 배포된 번호는 유지하고 재매핑 이력을 남긴다.

## 버전별 문서 관리

현재 계획 원본은 이 문서이며, 버전별 범위·상태·검증 근거와 문서 변경 이력은 `UPDATE_HISTORY.md`에서 관리한다. 계획 버전은 실제 배포 완료를 뜻하지 않는다. 구현·검증 후 실제 배포 식별자와 날짜를 연결한다.

townhall용 문안은 보관만 한다. 사용자가 별도로 게시를 요청하기 전에는 Slack에 전송하지 않는다. 2026-09-10 잘못 게시한 메시지는 사용자 요청에 따라 삭제 확인했다. 앞으로 문서 변경 이력을 갱신하면서 인터뷰를 이어간다.
