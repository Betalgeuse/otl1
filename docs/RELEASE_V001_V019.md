## 현재 사용 방법

원씽 채널에서 `오늘 원씽은 책 10쪽 읽기`, `책 다 읽었어요`, `절반 읽었어요. 시간이 부족했어요`, `오늘은 쉬기로 했어요`처럼 쓴다. 명확한 등록·수행 보고는 바로 처리하고, 모델이 애매하게 해석하면 확인 선택지를 보여준다. 일부 명확한 후기에도 보수적으로 확인을 요구할 수 있다.

저장 후 상태 카드·잔디·되돌리기를 제공한다. 목표 완료와 후기 제출은 별도다. `내 상태`, `알림 설정`, `샤라웃`으로 해당 기능을 열 수 있다. 운영자는 `회원 현황`, `업데이트 관리`, `피드백 보기`, `공통 안내 설정`을 사용할 수 있다.

- 원씽 채널의 공통 안내: 매일 한국 시간 **10:00 원씽, 18:00 후기**. 봇이 만든 각 스레드에 답하면 대상 날짜와 연결한다.
- 개인 추가 안내: 회원이 설정에서 켠 경우에만 종류별 하루 1회. 회원별 시각을 정할 수 있고 08:00~22:00 사이에만 발송한다. 등록·후기·휴식·중지 상태를 발송 직전에 다시 확인한다.
- 테스트 채널의 개인 안내와 공통 예약은 QA 종료 후 껐다. 실제 원씽 채널의 공통 안내만 켜 두었다.
- townhall 게시 기능은 구현·비공개 QA를 마쳤지만 현재 게시 대상 설정은 admin-dev다. 실제 townhall 공지는 보내지 않았다. 게시하려는 버전에 검증 표시가 있어야 운영자의 게시 버튼이 열린다.

Slack `/remind list`에서 정확히 원씽 10AM·후기 6PM 두 항목을 확인하고 각각 Delete를 눌렀다. 이후 `There are no more reminders.`를 확인했다. 증거: `.omx/qa/v001-v019/old-reminders-before.txt`, `old-reminders-after.txt`, `public-schedule.json`.

Cloudflare Cron은 등록·scheduled export를 확인했지만 실제 호출을 관찰하지 못했다. 원인을 코드라고 단정하지 않고, 검증 가능한 Durable Object 알람으로 전환했다. 채널마다 다음 예약 시각 하나를 저장하고 실행 후 다음 시각으로 재예약한다. 분당 DB 폴링을 없애며 Cron 설정도 제거했다. 공통 안내는 지연이 5분 이내일 때 보충하며 같은 날짜·종류 중복을 DB에서 차단한다. 기존 Slack 알림은 실제 알람 검증과 운영 예약 확인 후에만 제거했다.

## 데이터와 권한

- QA 상태는 채널별 별도 테이블에 저장해 공개 기록과 분리했다. 후기 안내 테스트의 임시 fixture는 원래 상태로 복구했고 더 새로운 수정이 있으면 덮어쓰지 않도록 검사했다.
- 공개 원씽 채널에는 출처가 확인된 8개 회원별 일일 기록과 이전 안내 스레드 6개의 날짜를 연결했다. [이력 범위·불확실성](qa/public-baseline.md). 기존 기록과 충돌하면 덮어쓰지 않았다.
- 공개 채널의 새 기록은 기존 목표 테이블에도 동기화해 기존 조회와 팔레트를 보존한다. QA 기록은 동기화하지 않는다. 기존 슬래시 명령의 모든 편집 경로를 이번에 재설계한 것은 아니다.
- 확인·되돌리기는 작성자와 채널을 확인한다. 이후 기록이 바뀐 오래된 되돌리기는 실제 UI에서도 거절했다. 잘못된 서명과 다른 작성자 요청은 별도의 HTTP 부정 테스트로 차단을 확인했다.
- 미참여·실패·휴식을 같은 상태로 합치지 않는다. 후기 없는 완료와 완료하지 못한 후기도 구분한다. 자동 퇴장·카카오 전송·경제 보상은 이번 범위가 아니다.

## 해석·표현의 한계

Qwen의 새 분류기 개발용 12문장 검증은 처음 9개가 일치했고, 일부 후기 표현은 보수적으로 확인으로 넘겼다. 불일치하는 모델 출력에 후기 근거가 있으면 ‘확인이 필요한 후기 후보’로 유지하도록 보완했다. 두 사례의 추가 실제 호출 결과를 별도 보존했다. 과거·인용·타인 보고·조작 지시 보호와 14개 경계 검증을 적용했지만, 모든 한국어를 정확하게 알아듣는다는 보장은 아니다.

im-not-ai 전체 CLI·다중 에이전트 파이프라인을 Worker에 설치한 것은 아니다. pinned 규칙 일부를 한국어 응원 지침으로 적용했다. 자유 생성에서 사실 추가가 관찰되어, 종류별 검토된 짧은 문구 네 개 중 Qwen이 선택하도록 제한했다. 직전 문구는 제외하고 이상한 출력은 남은 문구로 대체한다. `!!!`와 회원별 재미있는 이모지는 유지한다.

첫 달성은 채널에서 확인 가능한 기록 기준이다. 기존 이력이 불명확한 회원에게 생애 첫 달성이라고 단정하지 않는다. 잘못된 첫 축하는 정정하고, 되돌렸다 재완료하는 방식으로 첫 축하를 반복 발급하지 않는다. 샤라웃은 private QA에서 기존 회원을 대상으로 선택해 게시했으며 그 상대방의 실제 열람은 검증하지 않았다.

Slack 전송과 DB를 하나의 트랜잭션으로 묶을 수는 없다. 전송 결과가 불명확한 작업은 무조건 재시도하지 않아 중복을 줄이며 운영자 확인이 필요할 수 있다. 알림을 보내는 마지막 네트워크 요청 중에 사용자가 상태를 바꾸는 극히 짧은 경합은 남는다. 반응 실패는 목표 저장 성공과 구분한다.

- `bun run lint`, `bun run typecheck`, `bun run build` 통과.
