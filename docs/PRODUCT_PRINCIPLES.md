# OT1L 우선순위와 제품 운영 원칙

갱신: 2026-09-10. 우선순위 판단의 기준 문서다. 현재 인터뷰에서 확인한 방향과 제안한 실행 순서를 구분한다. 기능 추가는 이 문서를 기준으로 판단하고 [버전 목록](UPDATE_HISTORY.md)에 반영한다.

## 우리가 만들려는 결과

회원이 중요한 한 가지를 실제로 이루도록 먼저 챙기고, 놓쳤을 때 다시 참여할 기회를 준다. 내가 잘할수록 나를 믿고 초대한 지인에게도 좋은 결과가 돌아가는 관계를 만든다. 장기적으로 운영 비용과 보상을 감당하면서 운영자에게 이익이 남아야 한다.

성공은 회원의 실제 실천과 지속적인 참여, 지인 간 신뢰, 감당 가능한 운영 부담으로 판단한다. 메시지 수·초대 수·초록 칸 수·모델 호출 수만 늘었다고 성공으로 보지 않는다. 현재는 무료이며 수익화 시행 시점과 상품은 미정이다.

## 먼저 반응하고 함께 실천하는 분위기

**사람에 대한 신뢰, 풍부한 리액션, 자주 소통하되 균형 잡힌 접근**을 핵심 운영 원칙으로 둔다. 서로 잘 모르는 초기 회원도 원씽을 남겼을 때 누군가 봐주고 응원한다는 느낌을 받을 수 있어야 한다. 봇의 역할은 사람이 서로 반응하기 쉬운 분위기를 먼저 만드는 것이다.

- **기록이 조용히 묻히지 않게 한다.** 원씽을 등록하면 저장 여부를 명확히 알리고 여러 이모지와 짧은 응원 댓글로 반응한다. 완료는 함께 축하하고, 부분 수행·미완료 후기에는 실제 내용에 맞게 공감한다.
- **샤라웃이 사람 사이로 이어지게 한다.** 봇이 먼저 실제 원씽·후기를 근거로 서로 축하하고 감사할 기회를 제안한다. 회원은 직접 상대와 내용을 정해 샤라웃한다. 봇 명의의 축하와 회원이 자발적으로 보낸 응원을 구분한다.
- **첫걸음도 함께 축하한다.** 첫 원씽 완료와 첫 후기 제출을 각각 샤라웃한다. 첫 후기는 목표를 못 끝냈더라도 인정된 후기라면 그 참여를 축하하며, 목표 완료로 바꾸지 않는다.
- **먼저 다가간다.** 누락 후 요청만 반복하지 않고 원씽을 시작할 시점, 진행이 막힌 순간, 참여 공백 이후에 먼저 말을 걸어 습관을 이어갈 기회를 만든다.
- **대화는 원씽에 연결한다.** 오늘 한 가지를 정하기, 작은 다음 행동, 진행 상황, 후기, 휴식·재시작을 대화의 중심으로 삼는다. 자연스럽게 참여하도록 돕되 원씽과 무관한 잡담을 자동 등록하지 않는다.
- **빈도와 균형을 함께 본다.** 풍부한 이모지와 잦은 소통을 지향한다. 동시에 반응이 인기 회원에게만 몰리거나 특정 회원에게 댓글·DM·카카오가 연달아 쌓이지 않도록 한다. 공통 알림 한도와 회원의 선호·휴식·중지를 존중하며 횟수는 아직 미정이다.
- **눈에 보이는 반응과 직접 알림을 구분한다.** 이모지 여러 개, 스레드 댓글, 멘션, DM, 카카오가 만드는 부담은 다르다. 종류별 횟수와 회원별 전체 접촉을 함께 관리하고 Slack 알림 설정에 따른 실제 경험도 확인한다.
- **사람의 응원을 대신 꾸며내지 않는다.** 봇 반응은 봇이 한 것으로 표시한다. 초대자나 동료의 동의·응원처럼 위장하거나 회원 계정으로 자동 이모지를 달지 않는다. 봇 반응을 사람 간 신뢰나 동료 참여의 실적으로 세지 않는다.
- **실패와 휴식에도 존중을 유지한다.** 못한 일을 완료했다고 축하하지 않는다. 휴식을 선택하면 당일 의무 안내를 멈추며 쉬는 동안 재참여 요청을 반복하지 않는다. 복귀를 반기는 메시지와 죄책감을 주는 독촉을 구분한다.

운영에서는 반응받지 못한 기록, 회원별 반응 분포, 원씽 대화 뒤 실제 참여, 알림 피로·중지 요청을 함께 관찰한다. 이모지 수 자체를 성과 목표로 삼지 않는다. 카카오에 한 문장만 보내도 원씽을 남길 수 있는 경로는 참여 부담을 줄이는 후속 단계로 개발한다.

## 축하 말투와 이모지

v0.0.3의 적용 대상은 사용자가 지정한 imnotai의 원본 저장소 [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai)다. 공식 홈페이지는 https://imnotai.kr 이며 저장소 내부 스킬 이름은 humanize-korean이다. 2026-09-10 확인 기준 MIT 라이선스, 리비전 9747f036cdc28a1a8aea4dc71fef1f7846eb96f7을 참고 기준으로 기록한다. 로컬 설치본이 이 리비전과 같은지는 검증하지 않았다. 전체 CLI 실행 파이프라인을 Worker에서 그대로 실행하는 대신 허용된 한국어 표현 지침을 Qwen 응원 생성에 맞게 적용·검증하는 계획이다. 지침을 복사·수정하는 구현에서는 원본 저작권·라이선스 고지를 보존한다.

Qwen은 상태 분류용 구조화 결과를 반환하고, 응원은 검토된 문구 중에서 선택한다. 실제 적용 범위·원문 출처·제한은 [릴리스 결과](RELEASE_V001_V019.md)에 기록했다. 적용한 한국어 표현 지침은 응원 문구에 한정하며, 분류 JSON을 윤문하거나 사용자 후기 원문·수행 상태를 바꾸는 작업이 아니다. 우선 필요한 규칙만 짧은 프롬프트에 반영하는 안으로 비용을 관리하고, 별도 모델 재호출이나 파인튜닝을 자동으로 추가하지 않는다. 원본 지침의 이모지·느낌표 억제 규칙이 우리 축하 톤과 충돌하면 사용자가 정한 풍부한 표현을 우선한다.

축하는 친구들이 함께 신나 하는 말투로 짧게 쓴다. 느낌표를 여러 개 쓰고, 웃긴 이모지와 사람마다 다른 조합을 적극적으로 사용한다. ‘꾸준한 노력과 열정이 빛나는 순간입니다’처럼 누구에게나 붙일 수 있는 장황한 칭찬보다 실제 해낸 일을 바로 짚는다.

- 등록은 시작을 응원하고 완료는 해낸 것을 축하한다. 첫 후기는 기록을 남긴 행동을 축하한다. 서로 다른 상태에 같은 완료 문구를 붙이지 않는다.
- ‘첫 원씽 클리어!!!! 🦖🔥’, ‘첫 후기 등장!!! 기록까지 남겼다 🐣📝’처럼 짧고 구체적으로 반응한다. 아래 표현들은 운영용 예시이며 회원에게 보내지 않았다.
- 회원마다 좋아하는 이모지·리액션 톤을 반영한다. 선호가 없으면 재미있는 기본 세트에서 회원별로 조합을 달리하고, 최근 쓴 문구·조합이 계속 반복되지 않게 한다. 초기에는 템플릿 선택만으로도 구현할 수 있다.
- 같은 사람에게 같은 동물·별명을 영구적으로 붙이지 않는다. 이름·직장·학교만 보고 성격이나 취향을 추정하지 않는다. 개인화는 다른 대우가 아니라 서로 알아봐 주는 느낌을 위한 것이다.
- 축하에는 느낌표와 재미있는 이모지를 넉넉히 쓰되, 힘들다는 후기나 휴식에는 실제 내용과 회원 선호에 맞춰 강도를 낮춘다. 누구의 미완료를 웃음거리로 만들지 않는다.
- 텍스트 속 이모지와 Slack 리액션은 각각 지원되는 표현을 사용한다. 커스텀 이모지는 실제 워크스페이스에 있는지 확인하고 없는 경우 기본 이모지를 사용한다.
- 반응의 풍성함과 사람 간 균형을 유지한다. 문구·이모지 개수·선호 설정 방식은 구현 전에 구체화하며 모든 반응에 LLM 호출을 추가하지 않는다.

## 확인된 사용자 요구

- 명령어와 DM을 강제하지 않고 Slack 채널의 자연어로 등록·상태 변경을 지원한다.
- LLM을 사용하되 비용 효율을 우선한다. 버튼을 매번 강제하지 않는 방향이며 자동 처리 범위는 검증 후 정한다.
- 목표 등록, 실제 완료, 후기 제출, 휴식은 서로 다른 상태다. ‘오늘 쉬기’는 사유 없이 그날 참여를 마무리한다.
- 카카오는 후기뿐 아니라 원씽 등록 등 정해진 필수 행동의 누락도 안내한다. 외부 알림은 동의가 필요하다.
- 원씽 기록에 풍부한 봇 이모지·응원 댓글을 제공하고, 먼저 다가가 함께 습관을 지키는 분위기를 만든다. 빈도와 회원 간 균형을 함께 관리한다.
- 후속 단계에는 카카오 메시지로 원씽을 보내면 연결된 본인의 기록으로 Slack에 등록하는 경로를 제공한다. Slack에서만 입력해야 한다는 제한은 이 범위에서 확장한다.
- 지인 초대 관계를 보존하고 Silo 소속·경쟁·성과 보상을 연결한다. 초대 홈페이지에 카카오톡 또는 LinkedIn 정보를 관리할 계획이다.
- townhall 업데이트와 피드백 기능을 만든다. 다만 현재 계획은 문서에서만 관리하고 별도 게시 요청 없이 Slack에 보내지 않는다.
- 변경 하나에 v0.0.1 형식의 버전 하나를 부여한다. 새 기능은 우선순위에 맞춰 삽입하고 순서를 조정한다.
- 남은 우선순위 인터뷰를 먼저 진행한다. 이후에는 실제 사용자처럼 조작해 기능을 검증한다.

## 우선순위가 충돌할 때

1. 현재 발생하는 오류와 신뢰 훼손을 먼저 막는다.
2. 회원의 실제 실천을 막거나 운영자가 반복 수동 처리하는 문제를 앞에 둔다. 가능하면 사례·빈도·운영 시간을 근거로 남긴다.
3. 그 문제를 해결하는 데 필요한 선행 기능을 먼저 둔다. 편의상 의존성을 거꾸로 배치하지 않는다.
4. 효과가 비슷하면 더 작고, 운영 비용이 낮으며, 실제 사용으로 검증하기 쉬운 변경부터 한다.
5. 규칙이 미정인 기능은 임의 정책으로 구현하지 않는다. 인터뷰에서 결정하거나 독립적인 다음 후보를 앞으로 옮기고 재정렬 사유를 기록한다.

예: 카카오 원씽 미등록 안내는 늦게 나온 요구라도 수익화 뒤에 붙이지 않고 필수 행동 지원 순서로 올린다. 반면 보상 기능은 지급 재원·성과 인정 기준이 없으면 앞당기지 않는다.

## 버전 관리 원칙

- **한 버전, 한 결과.** 등록과 후기 저장을 한 덩어리로 묶지 않는다. 단, 등록 버튼·저장·응답처럼 한 결과에 필요한 요소는 함께 구현한다.
- **버전이 작업 식별자다.** 별도 작업 번호와 중복 백로그를 만들지 않는다. 문서 편집은 날짜별 이력으로 남긴다.
- **미출시 계획은 재정렬한다.** 신규 요구를 끝에만 붙이지 않는다. 우선순위와 선행 조건을 비교해 위치를 정하고 번호·현재 문서의 참조·의존성을 함께 갱신한다.
- **출시 번호는 고정한다.** 배포된 버전 번호는 바꾸거나 재사용하지 않는다. 미출시 계획을 재번호화할 때도 출시 번호와 충돌시키지 않는다.
- **변경 이력을 남긴다.** 추가·분할·이동 이유, 이전 번호와 새 번호, 바뀐 범위와 미정 사항을 기록한다. 과거 이력의 당시 번호는 현재 번호로 조용히 덮어쓰지 않는다.
- **계획과 완료를 구분한다.** 각 버전에 결과 하나, 완료 조건, 선행 조건, 상태를 적는다. 배포할 때 날짜·배포 식별자·검증 근거·남은 제한을 연결한다.

## 제품 동작과 검증 원칙

- 명확한 자연어는 검증된 범위에서 처리 결과와 되돌리기를 제공하고, 애매한 말은 본인에게 확인한다. LLM은 해석을 맡으며 권한·저장·발송·보상 규칙은 코드가 적용한다.
- 후기를 썼다고 목표 완료로 바꾸지 않는다. 완료하지 못한 것, 응답이 없는 것, 휴식을 선택한 것을 구분한다.
- 등록·후기 등 안내가 여러 개여도 개인별 총 알림 한도를 공유한다. 해당 행동 완료·휴식·중지·동의 철회에 맞춰 관련 안내를 중단한다.
- 카카오 메시지의 Slack 공개는 본인 연결과 공개 범위를 확인한 뒤 수행한다. 명확한 원씽만 등록하고 애매한 말은 확인한다. 수신 재전송·Slack 게시 재시도로 중복 목표나 중복 공지를 만들지 않는다.
- 자동 퇴장과 경제 보상은 LLM 판정만으로 실행하지 않는다. 대상·유예·복귀·지급·환불 등 필요한 정책을 먼저 정한다.
- 무료 운영 인원은 실제 관리 부담을 보며 정한다. 현재 30명·50명·4주 관찰은 제안이다. 인원 달성이 곧 유료화 조건은 아니다.
- 비용은 LLM뿐 아니라 운영자 시간·카카오·결제·프로그램 제공·보상까지 본다. 목표는 매출 발생 이후에도 운영자에게 실제 이익이 남는 구조다.
- 코드 검사와 API 성공만으로 사용자 기능이 완료됐다고 하지 않는다. 해당 버전의 실제 채널 입력·버튼 또는 자연어 확인·저장·응답을 직접 조작하고 검증한다. 없는 버튼이나 연결되지 않은 저장을 완료로 안내하지 않는다.
- 문서 변경은 외부 게시 권한이 아니다. townhall 게시 기능을 계획하거나 구현하는 것과 실제 공지를 보내는 것은 별개다.

## 2026-09-11 원씽 안내·커스텀 반응 원칙

원씽은 단순히 오늘 꼭 해낼 일 하나가 아니라 **오늘 최우선순위로 가장 먼저 해결할 중요한 일 한 가지**다. 등록·공통·개인 안내는 이 기준으로 묻는다. 사용자가 기록한 목표를 봇이 임의로 다른 목표로 바꾸지는 않는다.

봇은 참여를 부탁하는 데서 끝내지 않고 직접 리액션을 단다. 장식과 응원에 쓰는 이모지는 가능한 한 워크스페이스 커스텀 목록에서 무작위로 선택하고 한 번의 반응 안에서는 중복을 피한다. 실제 선택한 리액션을 저장해 정정·되돌리기를 맞춘다. 회원 원문과 의미가 있는 상태 표시는 보존한다.
