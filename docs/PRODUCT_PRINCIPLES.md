# 제품 원칙

회원이 **오늘 최우선순위로 가장 먼저 해결할 중요한 일 한 가지**를 실제로 이루도록 돕습니다. 내가 잘할수록 나를 믿고 소개한 지인에게도 좋은 결과가 돌아가는 관계를 지향합니다.

## 사람과 실천이 중심

- 성공은 실제 실천·지속 참여·지인 간 신뢰·감당 가능한 운영 부담으로 판단합니다. 메시지·이모지·초록 칸·초대 수만 늘어난 것은 성공이 아닙니다.
- 봇이 먼저 반응하고 다가가되, 사람이 서로 응원하기 쉬운 분위기를 만듭니다. 봇의 축하를 회원의 자발적 응원처럼 꾸미지 않습니다.
- 풍부한 리액션과 잦은 소통을 지향하면서 회원별 반응 편중과 접촉 부담을 함께 봅니다. 댓글·멘션·DM·외부 알림은 같은 부담으로 취급하지 않습니다.
- 완료, 부분 진행, 미완료, 응답 없음, 휴식을 구분합니다. 못한 일을 완료로 칭찬하거나 휴식에 죄책감을 주지 않습니다.
- 목표 등록·실제 완료·후기는 별개의 행동입니다. 대화는 기록·작은 다음 행동·진행·휴식·재시작에 연결하고 잡담을 자동 목표로 만들지 않습니다.

## 표현과 신뢰

축하는 실제 행동을 짧고 구체적으로 짚고, 느낌표와 재미있는 커스텀 이모지를 충분히 사용합니다. 힘든 후기와 휴식에는 강도를 낮춥니다. 같은 동물·별명을 영구히 붙이거나 이름·회사·학교만으로 취향을 추정하지 않습니다.

회원 원문과 수행 상태를 임의로 윤문하지 않습니다. 한국어 응원에 참고한 자료의 [출처와 라이선스](vendor/im-not-ai/README.md)는 유지합니다. 현재 반응·환영·축하 동작은 [운영 가이드](OPERATIONS.md), 구체적 입력법은 [사용 가이드](USER_GUIDE.md)가 원본입니다.

## 우선순위 판단

1. 잘못된 저장, 타인 기록 변경, 오알림, 데이터 손실을 먼저 막습니다.
2. 실제 참여를 막거나 운영자가 반복 수동 처리하는 문제를 앞에 둡니다.
3. 필요한 선행 기능을 먼저 갖춥니다. 홈페이지나 외부 연동을 불필요한 전제조건으로 만들지 않습니다.
4. 효과가 비슷하면 작고, 운영 비용이 낮고, 실제 사용으로 검증하기 쉬운 변경을 선택합니다.
5. 정책이 미정이면 임의로 확정하지 않습니다. 결정 질문을 남기고 독립적으로 가능한 작업을 비교합니다.

실행 순서와 남은 질문은 [로드맵](ROADMAP.md)에서만 관리합니다. 새 요구가 기존 목적이나 미해결 요구를 조용히 지우지 않게 합니다.

## 변경·검증 기준

- 이론을 근거로 설계·운영을 고민할 때마다 [설계 일지](research/DESIGN_JOURNAL.md)에 판단 과정과 출처·한계·확정 여부를 남깁니다. 이후 판단이 바뀌면 후속 기록으로 연결합니다.
- 한 버전은 관찰 가능한 결과 하나입니다. 그 결과에 필요한 화면·저장·응답·검증은 함께 포함합니다.
- 버전이 작업 식별자입니다. 별도 U 번호나 중복 백로그를 만들지 않습니다.
- 출시 번호는 고정합니다. 미출시 계획은 우선순위에 따라 재정렬하되 의존성과 현재 참조를 함께 바꾸고 구번호→신번호 이력을 남깁니다.
- 문서 정리는 날짜로 기록하며 기능 출시로 세지 않습니다. 출시 결과는 [업데이트 이력](UPDATE_HISTORY.md), 향후 작업은 로드맵으로 분리합니다.
- LLM은 해석을 돕고 권한·날짜·저장·발송·보상 규칙은 코드로 적용합니다. 모호한 말은 확인하며 모델에게 모든 결정을 맡기지 않습니다.
- 실제 입력·저장·응답을 검증합니다. 테스트 통과나 API 성공만으로 사용자 기능을 완료했다고 하지 않습니다. 유한 QA를 모든 자연어·모든 장애의 해결로 주장하지 않습니다.
- 문서 변경은 외부 게시 권한이 아닙니다. 계획·구현·실제 공지 발송을 구분합니다.

## 참여 자격과 소개의 경계

- lifecycle은 Slack 디렉터리 소속과 별개입니다. 공통 목표 프롬프트와 완전한 회원 스냅샷이 성공한 날짜만 관측 평일로 세며, 7개 뒤에는 먼저 shadow 근거를 확인합니다. 주말, 온보딩 전, 승인 유예, 수집 실패, 미해결 정정은 후보 근거가 아닙니다.
- 시행 뒤에도 7일 유예를 먼저 알리고, 본인은 이유를 쓰지 않고 한 번만 7일 연장할 수 있습니다. 유예 종료는 현재 잔디 시즌과 과거 기록을 보존하고 개인 안내·소개 링크를 멈추는 일입니다. Slack 계정이나 채널에서 강퇴·비활성화하지 않습니다.
- 휴면 회원은 새 현재 날짜 ONE THING을 실제로 저장할 때만 즉시 돌아옵니다. 후기·과거 수정·버튼만으로는 복귀하지 않습니다.
- 회원 자격은 확인된 기존 회원의 소개로만 시작합니다. 소개 링크는 관계 출처를 남기며, 소개자는 승인·거부·한도 변경·지원자 정보 접근 권한을 갖지 않습니다. 단계적으로 여는 즉시 참여 경로에서는 이메일 동의와 Turnstile을 통과한 뒤 공식 Free Slack 공유 초대로 이동하고, Slack 계정 이메일이 신청 digest와 정확히 일치한 `team_join`만 소개 출처로 기록합니다.
- 초대 한도는 전역 기본값과 회원별 예외를 운영자만 lifetime으로 조정합니다. 기본값은 2명이고, 실제 가입과 `approved` 예약만 세며 월별 초기화는 없습니다. pending 소개 신청과 비소속자 관심 문의는 한도를 예약하지 않으며, 가입 뒤의 출처도 계속 셉니다.
- 소개 링크가 없는 사람의 공개 사이트 문의는 운영자 전용 비공개 문의일 뿐 가입·소개·할당량 예약·Slack 초대가 아닙니다. `interest-consent-v1`과 `invite-consent-v1`은 서로 별도로 받아야 하며, 이름·이메일을 확인된 회원에게 보여 주는 동의는 선택 사항입니다. 공유를 거부하면 임의의 오프라인 digest로 대신 확인하거나 봇이 소개를 붙이지 않습니다.
- 소개 링크 없는 공개 문의는 즉시 참여로 전환하지 않습니다. 공유 초대 URL은 최종 방문자에게 노출될 수 있으므로 회수·교체 가능한 운영 자격으로 다루며, 이메일이 일치하지 않는 가입은 누구의 소개로도 추정하거나 한도에 차감하지 않습니다.
- 위 항목은 [로드맵](ROADMAP.md)의 v0.0.56–v0.0.66 미출시 계획입니다. 같은 exact SHA의 배포·Slack Web·브라우저 관찰 전에는 현재 운영 정책으로 바꾸지 않습니다.

## 아직 확정하지 않은 정책

현재 커뮤니티는 무료이며 유료 상품·시점은 미정입니다. 장기적으로 운영자 시간과 서비스 원가·보상까지 고려해 운영자에게 이익이 남아야 합니다. 제안된 인원수나 관찰 기간이 자동 유료화 조건은 아닙니다.

지인 소개 관계는 입장 경로의 출처로 보존하되 별도 초대권·월별 장수·Silo 소속으로 권한을 만들지 않습니다. Silo 배정·이동·경쟁은 활성 계획에서 제외하고, 웹사이트는 소개용 공개 페이지로 한정합니다. 외부 연락처 연결과 발송·공개 동의를 구분합니다. 자동 제외·복귀·경제 보상은 기준·유예·재원·환불 등을 정한 뒤 진행하며 LLM 판단만으로 실행하지 않습니다. 세부 미정 항목과 버전은 로드맵에 남깁니다.
