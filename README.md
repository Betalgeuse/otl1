## 사용자가 정한 방향

- 작게 시작하고, 기능을 조금씩 늘린다.
- 슬랙 자기개발 커뮤니티에서 하루 한 문장으로 목표를 만든다.
- GitHub 기여 잔디처럼 칸을 채우는 방식으로 참여를 표현한다.
- 처음에는 4칸, 그다음에는 8칸으로 차근차근 진행한다.
- 각 칸은 미작성·작성·완료 상태를 가지며, 기본색은 각각 회색·연두색·초록색이다.
- 사용자가 원하는 색상을 선택할 수 있어야 한다.
- 날짜와 Day 번호의 순서·정렬이 깨지지 않아야 하며, 모바일에서도 깔끔하게 보여야 한다.

## 칸의 상태와 개인 색상 설정

| 상태 | 의미 | 기본색 |
| --- | --- | --- |
| 미작성 | 해당 칸에 목표를 작성하지 않음 | 회색 |
| 작성 | 목표를 작성했고 아직 완료하지 않음 | 연두색 |
| 완료 | 작성한 목표를 본인이 완료 처리함 | 초록색 |

목표 작성과 완료는 같은 칸의 상태를 바꾼다. 완료할 때 다른 칸을 추가하지 않는다. 작성했지만 완료하지 않은 목표는 작성 상태를 유지한다.

색상 설정 방식은 다음과 같이 제안한다.

- 개인 설정에서 세 상태의 색을 각각 선택하고 저장한다.
- 기본 제공 색상 목록과 직접 색상 코드 입력을 제공한다. 기본색으로 복원할 수 있다.
- 저장 전 현재 보드로 미리보기를 제공한다.
- 선택한 색상은 해당 사용자의 보드에 적용하며, 목표 날짜·내용·완료 기록은 바꾸지 않는다.
- 색만으로 상태를 전달하지 않는다. 보드에 작성·완료 건수와 상태 범례를 함께 표시하고, 이미지 대체 텍스트에도 각 칸의 상태를 제공한다.
- 과거에 전송된 보드 이미지까지 갱신할지는 미정이다. 우선 현재 보드와 이후 생성되는 표시에 적용하는 방식을 제안한다.

## 첫 참여 흐름 제안

1. 전용 채널에 오늘의 원씽을 한 문장으로 등록한다.
2. 등록하면 해당 칸이 연두색으로 바뀌고, 본인이 완료 처리하면 같은 칸이 초록색으로 바뀐다. 미작성 칸은 회색이다. 색상 설정을 변경했다면 해당 사용자의 색을 적용한다.
3. 4칸에서 8칸으로 진행한다. 날짜 경과와 전체 완료 중 무엇을 전환 기준으로 삼을지는 아직 정하지 않았다.
4. 봇이 해당 목표의 스레드에 현재 진행 상태를 보여준다.

예시 목표: “저녁에 책 10쪽 읽기.”

```text
첫 보드 · 완료 2 · 작성 중 1 · 미작성 1
[완료][완료][작성][미작성]
 초록  초록  연두   회색
```

이 예시는 상태 구분을 설명하는 텍스트이며 실제 UI가 아니다. 이전 초안의 “4회 완료 후 새 8칸 보드 시작”은 미확정 제안이다. 날짜별 칸으로 운영할지, 완료 횟수로 다음 단계에 진입할지 먼저 정해야 한다. 새 보드 시작과 기존 보드 확장 중 어느 방식을 쓸지도 미정이다.

## 작게 시작하기 위한 운영 규칙 제안

- 하루 한 사람당 한 칸에 목표를 등록하고 그 칸의 상태를 갱신한다. 하루 경계는 한국 시간 기준으로 제안한다.
- 쉬는 날에는 기존 칸을 유지한다. 연속 출석 조건은 두지 않는다.
- 다른 사람의 응원 리액션은 완료로 처리하지 않는다.
- 같은 작성·완료 이벤트가 반복 전달되어도 칸이나 집계가 늘어나지 않는다.
- 개인 보드를 슬랙 안에서 공유하는 것으로 시작한다.
- 목표 수정, 완료 취소, 날짜가 지난 목표의 완료 처리는 구현 전에 규칙을 정한다.

## 날짜 정렬과 모바일 표시 제안

권장안은 날짜가 고정된 하루 한 칸과 4열 보드다. 아래는 사용자의 모바일·정렬 요구를 만족하기 위한 설계 제안이며 실제 Slack 화면을 검증한 결과는 아니다.

### 날짜와 순서

- 시작 날짜를 Day 1에 고정한다. Day 번호는 시작일부터 지난 달력 날짜 수에 1을 더해 계산한다. 완료 횟수와 분리한다.
- 날짜 기준은 Asia/Seoul로 고정하는 방식을 제안한다. 휴대폰의 시간대가 달라져도 기존 날짜와 Day 번호를 다시 배정하지 않는다.
- 날짜별 칸을 먼저 만들고 그 날짜의 기록을 채운다. 미작성 날도 회색 칸으로 남겨 뒤의 기록이 앞으로 당겨지지 않게 한다.
- 목표 수정, 완료 처리, 색상 변경은 해당 칸만 갱신한다. 작성·완료 순서로 재정렬하지 않는다.
- 미래 칸은 아직 참여할 날이 아니므로 회색 바탕에 테두리와 “예정” 표식을 붙인다. 이는 네 번째 목표 상태가 아니라 날짜에 따른 표시다. 오늘 칸에는 “오늘” 표식을 붙인다.
- 저장은 연도를 포함한 날짜와 숫자 Day 번호를 사용한다. 화면의 “9/8”이나 “Day 10” 문자열로 정렬하지 않는다.

### 4칸에서 8칸으로

기존 4칸 아래에 다음 4칸을 붙여 총 8칸으로 확장하는 안을 추천한다. 첫 4칸의 날짜·색·위치가 그대로 남는다. 날짜 기준으로 운영한다면 Day 5에 확장하며, 미완료 기록이 있어도 다음 날을 기록할 수 있다. 이전의 “완료 후 새 8칸 보드” 제안을 대체할 후보이고 아직 확정하지 않았다.

```text
Day 1   Day 2   Day 3   Day 4
 9/8     9/9    9/10    9/11
 [칸]    [칸]    [칸]    [칸]

Day 5   Day 6   Day 7   Day 8
9/12    9/13    9/14    9/15
 [칸]    [칸]    [칸]    [칸]
```

이 텍스트는 배치 설명용이다. 실제 Slack 메시지를 공백 정렬로 구현하지 않는다.

### 모바일 화면

- 4칸은 4열 1행, 8칸은 4열 2행으로 표시한다. 모바일에서도 열 수와 읽는 순서를 유지한다.
- 각 칸 위에 Day 번호를 주 표기로, 짧은 날짜를 보조 표기로 둔다. 제목에는 연도를 포함한 기간을 표시한다.
- 칸·번호·날짜를 하나의 PNG 보드 이미지에 함께 그리는 안을 추천한다. 이미지 내부 좌표를 고정해 텍스트 줄바꿈에 따라 칸과 날짜가 어긋나지 않도록 한다.
- 이미지는 글자까지 함께 축소되므로 좁은 메시지 폭에서 읽을 수 있도록 처음부터 모바일 폭으로 설계한다. 원본 해상도만 높이는 것으로 작은 글자 문제를 해결했다고 간주하지 않는다.
- 보드 아래에 오늘의 목표와 “완료 2 · 작성 중 1” 같은 요약을 Slack 텍스트로 표시한다. 긴 목표 문장은 보드 이미지 안에 넣지 않는다.
- 이미지의 칸을 누르는 조작을 전제로 하지 않는다. 오늘의 상태에 맞는 기본 버튼 한 개와 “기록 보기”, “설정” 메뉴를 제공하는 안을 제안한다. 날짜별 내용은 기록 보기에서 날짜를 선택해 읽는다.
- 상태 범례와 대체 텍스트를 제공하며, 사용자가 비슷한 색을 선택해도 상태를 확인할 수 있어야 한다.

Slack [이미지 블록 문서](https://docs.slack.dev/reference/block-kit/blocks/image-block/)는 PNG와 대체 텍스트를 지원한다. 이 기능을 이용한 설계 제안이며, 이미지 생성·전달·갱신은 구현 후 실제 클라이언트 검증이 필요하다.

### 구현 후 검증할 화면과 경계

- 모바일 세로 화면에서 4칸과 8칸의 Day·날짜·상태가 확대 없이 읽히는지 확인한다.
- iOS·Android Slack의 밝은/어두운 테마와 데스크톱에서 이미지, 요약, 버튼을 확인한다. 브라우저 폭 검사만으로 모바일 Slack 검증을 대신하지 않는다.
- Day 9에서 10으로 바뀌는 경우, 월말·연말·윤일, 한국 시간 자정 전후에도 날짜 매핑이 유지되어야 한다.
- 중간 미작성, 과거 기록 갱신, 늦게 도착한 이벤트가 뒤의 칸 위치를 바꾸지 않아야 한다. 과거 갱신 허용 여부와 별개로 이벤트는 원래 목표 날짜에 귀속한다.
- 이미지 표시 실패 시에도 텍스트 요약과 기록 보기로 상태를 확인할 수 있어야 한다.

## 기술 후보

Slack HTTP 이벤트 → Cloudflare Workers → Neon PostgreSQL.

앞선 대화에서 추천한 구성이며 사용자가 최종 선택한 것은 아니다. 이는 초기 검토 기록이며, 현재 운영·배포 상태는 문서 상단의 버전 목록을 따른다.

Slack의 [선택 메뉴](https://docs.slack.dev/reference/block-kit/block-elements/select-menu-element/)와 텍스트 입력을 설정창에 사용하는 방식을 제안한다. 사용자 지정 색상 보드는 생성한 이미지를 [이미지 요소](https://docs.slack.dev/reference/block-kit/block-elements/image-element/)로 표시하는 후보를 검토한다. 이는 문서에 근거한 설계 제안이며 Slack에서 실제 렌더링·갱신을 검증하지 않았다.

## 구현 시 확인할 동작

- 미작성 칸은 기본 회색이고, 목표 작성 시 같은 칸이 연두색으로 바뀐다.
- 본인이 완료하면 같은 칸이 초록색으로 바뀌고, 중복 이벤트는 결과를 바꾸지 않는다.
- 완료하지 않은 작성 기록은 작성 상태로 남는다.
- 사용자가 상태별 색을 저장하면 자신의 보드에 반영되고, 다른 사용자의 설정은 유지된다.
- 색상 변경과 기본색 복원은 목표 기록과 완료 집계를 바꾸지 않는다.
- 상태 요약과 이미지 대체 텍스트만으로도 작성·완료·미작성을 구분할 수 있다.

## 다음에 결정할 핵심

작성과 완료를 서로 다른 색으로 표시한다는 기준과 모바일·정렬 요구는 확정했다. 날짜 정렬에 맞춰 “하루 한 칸, Day 5에 기존 4칸을 총 8칸으로 확장”을 추천한다. 이 권장안을 사용할지, 완료 횟수에 따라 새 보드로 넘어갈지는 아직 확정하지 않았다.

이후 보드 확장 방식과 개인·공동 소유 범위, 완료 취소 규칙을 확정한다. 작은 운영 실험에서는 첫 보드 완성 여부와 다시 참여하는 사람의 비율을 관찰하되, 성공 기준 수치는 아직 정하지 않았다.
